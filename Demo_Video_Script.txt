PART 1 - Introduction  (0:00 - 0:20)
>> Show: Presentation.pptx, slide 1 (title).
-------------------------------------
This project predicts the asking price of land in the Colombo district. There's
no public, plot-level price guide in Sri Lanka, so I built a machine learning
model that estimates a fair price per perch from a plot's area, size and land
type, and deployed it as a web app that also explains its predictions.


PART 2 - How the project was implemented  (0:20 - 1:40)
>> Show: VS Code with the Assignment_2 folder open in the Explorer.
-------------------------------------------------------
I built the project in four notebooks, plus an application and an automated
pipeline.
>> Click 01_data_preparation.ipynb.
In the first notebook I cleaned the data: 4,494 Kaggle land listings. I chose
price per perch as the target, fixed listings priced per acre, removed
duplicates, and log-transformed the skewed prices before removing outliers,
which left 4,275 clean listings. I also explored the data. Location is by far
the strongest driver of price.
>> Click 02_modelling.ipynb.
In the second notebook I trained and tuned the models with five-fold
cross-validation and compared them on a held-out test set.
>> Click 03_unseen_areas.ipynb, then 04_explainability.ipynb.
The third notebook tests the models on areas they have never seen, and the
fourth explains them with SHAP, LIME and partial dependence plots.
>> Click app.py, then explain.py.
The final model is saved as a pickle file, which this Streamlit app loads. The
explain file adds a SHAP explanation to every prediction.
>> Click the src folder, then tests, then .github/workflows.
For MLOps, the src folder holds a retraining pipeline with a quality gate, the
tests folder holds 15 automated tests, and GitHub Actions runs those tests on
every push. The project is on GitHub, and Streamlit Cloud redeploys the app
automatically.


PART 3 - Model accuracy  (1:40 - 2:30)
>> Show: slide 4 (accuracy table). Point at each row as you mention it.
--------------------------------------
This table compares all the models. The baseline is Ridge regression. Random
Forest and XGBoost were taught in the module, and tuning them lifted R-squared
from about 0.83 with default settings to 0.86. The ranking uses cross-validated
error on the training data, so the test set wasn't used to make choices. The
final stacking model reaches an R-squared of 0.866 on the test set, with a
median error of about 12 percent.


PART 4 - Why this model  (2:30 - 3:00)
>> Show: slide 4, right-hand panel.
--------------------------------------
My new algorithm is CatBoost, which wasn't covered in the lectures. The area
column has 160 categories, many with very few listings, and CatBoost encodes
them without leaking the target price. It tied for the best test score and was
the best on unseen areas. The final model stacks Random Forest, XGBoost and
CatBoost, because that combination had the lowest cross-validated error.
