PART 1 - Introduction  (0:00 - 0:20)
>> Show: Presentation.pptx, slide 1 (title).
-------------------------------------
This project predicts the asking price of land in the Colombo district. There's
no public, plot-level price guide in Sri Lanka, so I built a machine learning
model that estimates a fair price per perch from a plot's area, size and land
type, with a likely price range, and deployed it as a web app that also explains
its predictions.


PART 2 - How the project was implemented  (0:20 - 1:30)
>> Show: the GitHub repository page, github.com/amalr-12/colombo-land-price-ml
   (signed in). Scroll down slowly to the README's "Repository structure" box.
-------------------------------------------------------
The whole project is in this GitHub repository. It's built in five notebooks.
The first cleans the data: 4,494 Kaggle land listings, with the price per
perch as the target, a unit error fixed, duplicates removed, and prices
log-transformed before removing outliers, leaving 4,275 clean listings. The
second trains and tunes the models with five-fold cross-validation. The third
tests them on areas they have never seen, the fourth explains them with SHAP,
LIME and partial dependence plots, and the fifth trains NGBoost, my new
algorithm. The trained models are saved as pickle files, which the Streamlit
app loads, and the explain file adds the SHAP explanation and the NGBoost price
range to every prediction.
>> Scroll down to the "MLOps pipeline" diagram in the README.
For MLOps, a retraining pipeline rebuilds the models from the raw data, and a
quality gate only replaces the deployed model if the new one is good enough.
>> Click the "Actions" tab at the top of the repository.
Seventeen automated tests run on every push, which are these green ticks, and
Streamlit Cloud redeploys the app automatically.


PART 3 - Model accuracy  (1:30 - 2:20)
>> Show: slide 4 (accuracy table). Point at each row as you mention it.
--------------------------------------
This table compares all the models. Ridge, Random Forest, XGBoost, LightGBM,
CatBoost and stacking were taught in the module; NGBoost, highlighted in blue,
is my new algorithm. Tuning lifted R-squared from about 0.83 with default
settings to 0.86. The ranking uses cross-validated error on the training data,
so the test set wasn't used to make choices. The final stacking model reaches an
R-squared of 0.866 on the test set, with a median error of about 12 percent.


PART 4 - Why this model  (2:20 - 2:50)
>> Show: slide 4, right-hand panel.
--------------------------------------
My new algorithm is NGBoost, which wasn't covered in the lectures. Every taught
model predicts one number, but asking prices are noisy, so a single number
hides the uncertainty. NGBoost predicts a whole probability distribution of the
price, so it gives a range. It ranks third of eight on cross-validated error,
and its 80 percent ranges contain 82 percent of actual prices. The final price
model stacks Random Forest, XGBoost and CatBoost, because that had the lowest
cross-validated error, and NGBoost adds the range.
